**Language rule:** every definition, contract and doc in this repo is written in English. Bots and

**Changes in rev 3**

- The graph is no longer a central element. It moves behind a button (P4) and opens the current
  viewer as-is.
- The centre of the product is a **snapshot feed**: every state-changing event produces an immutable
  forecast snapshot. The timeline scrolls through snapshots, not through a list of cards.
- Left panel = state at the selected date plus the selected analysis/document.
- Right panel = what was forecast and recommended on that date, whether it was done or ignored, and
  how much the forecast has drifted since.
- Five priority levels stay.

## 1. Verdict: is it ready for a manager?

**No.** There is a working 3D viewer and an honest defect list, but no product: no user scenarios,
no data contract, no definition of done.

| Layer | State | Where |
|---|---|---|
| 3D body, 8 layers, 104 organs, 19 female structures | works, rendered | `body/index.html`, `body/models/` |
| Store + fixture (create/connect/delete, localStorage) | works | `body/store.js`, `body/fixture.js` |
| Demo data | **hard-coded in the page** (`SAMPLE_ANALYSES`, `1984-03-01`) | `body/index.html` |
| App identity | **science**, not health: `app.json` byte-identical to science | `app.json` |
| App catalog | knows only `viewer` | `1M_kg_skill/scripts/apps.json` |
| Timeline / profile / estimates / snapshots | **missing** | — |
| Docs | rich, but history and bug list, not a backlog | `HANDOVER.md`, `HISTORY.md` |

Blockers: no data contract; demo not separated from user data; no measurable acceptance criteria.

## 2. Priority levels

| Level | Meaning | Rule |
|---|---|---|
| **P0** | Nothing else can start without it | contract, identity, demo separation |
| **P1** | Base product: what people pay for | timeline + snapshots + estimates |
| **P2** | Extensions that raise value | agent import, predictions, demo case |
| **P3** | Improvements and skills | new models, prediction skill, release |
| **P4** | Showcase and experiments | graph view, 3D, heavy assets |

Estimate rule: base scales ship in P1; **every possible improvement goes to the backlog with value
and effort**, never "we'll decide later". Estimate quality is the core value of the product.
